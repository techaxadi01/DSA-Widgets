How it works


    

  • A max-heap from a min-heap. Python’s heapq always keeps the smallest item on top. Storing -num flips the order, so the largest number becomes the smallest entry and rises to the top. We negate it again when reading the answer.
    • 

  • Why store the index. The heap alone cannot tell which numbers have left the window. Pairing each value with its index lets us ask whether the top is expired: index <= i - k means it is no longer among the last k numbers.
    • 

  • Lazy deletion. We do not search the heap for expired entries. We only check the top. An expired entry buried deeper is harmless, because it cannot affect the answer until it reaches the top, and then the while loop removes it. The dashed chips show this.
    • 

  • Why while, not if. Several expired entries can stack up at the top, so one pop may not be enough.
    • 

  • Why the heap is never empty. We push index i just before the check, and i > i - k always (since k is at least 1), so the loop always stops.
    • 

  • Cost. Each number is pushed and popped at most once, and each heap operation is O(log n), so time is O(n log n). Space is O(n), because buried expired entries stay in the heap. A monotonic deque solves the problem in O(n) time and O(k) space.
    • 

  • The code uses heapq, which needs import heapq at the top. LeetCode adds this for you.
    • 



Edge cases to try


Try 5, 5, 5, 5 with k = 2 (ties), 9, 8, 7, 6 with k = 2 (the max keeps expiring), 1, 2, 3, 4 with k = 4 (a single window), and 4, 2 with k = 1 (every number is its own window).
