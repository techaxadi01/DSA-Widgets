OPERATION LOG
← ENQUEUE adds to the rear. DEQUEUE removes from the front. Watch the costs diverge.
A queue demands two things: add to the rear, remove from the front. For a linked list with a tail pointer, both are O(1) — change one pointer each time. For a naive array, adding to the rear is fine — but removing from the front forces every remaining element to shift left. One DEQUEUE on an array with n elements costs n−1 moves.

There IS an O(1) array queue: the circular buffer — keep two indices, front and rear, and wrap them around the array. Both ENQUEUE and DEQUEUE become O(1). But it requires careful index arithmetic and a fixed capacity. The linked list gives you O(1) naturally, without the complexity. This is why most queue implementations in systems programming use a linked list — or a linked list of fixed-size chunks for cache efficiency.

In our BFS contact trace: we need to DEQUEUE frequently (once per person traced) and ENQUEUE frequently (once per contact discovered). Both being O(1) is not optional at scale — it's what makes BFS run in O(V + E) time.
