Example. Same algorithm, but now the cycle B→C→D→B costs 3 + (−6) + 2 = −1. Step through what Dijkstra does, then switch on the naive version to see what happens when it is not allowed to ignore the better route.

Why no shortest path can be computed

  1. Every lap pays you. Going once around B→C→D→B costs −1, so each lap makes the walk from A to B one unit cheaper. The same is true for C, D and E, since all of them are reachable through the cycle.
  2. "Shortest" needs a minimum to exist. The costs of walks from A to B are 2, 1, 0, −1, −2, … With no lower limit there is no smallest one. The true distance is −∞, not a number.
  3. Dijkstra's proof stops working. It says: the vertex with the smallest tentative distance is final, because any other route must pass through a vertex at least as far away and adding edges never lowers the cost. A negative edge breaks the last part. Here D ends up at −1, below B's "final" 2.
  4. Only vertices reachable from the cycle are affected. A stays at 0. Bellman–Ford handles negative edges and also detects this case: if an edge can still be relaxed on the V-th pass, a negative cycle is reachable from the source.
