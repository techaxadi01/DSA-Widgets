Priority queues

Same interface, two implementations. Run operations and compare how many comparisons and moves each one costs.

Min-priority queue: INSERT adds an item, EXTRACT-MIN removes the smallest, PEEK-MIN reads it. With a plain array you pick one of two bargains: keep it unsorted (cheap insert, costly search) or keep it sorted (costly insert, cheap search). Switch between them and try the same operations on both.

  • Unsorted. INSERT writes to the next free slot. EXTRACT-MIN must compare against every item, so it always does n−1 comparisons, in the best case too. Removing the minimum is cheap afterwards: copy the last item into the hole.
  • Sorted descending. The minimum sits at the end, so EXTRACT-MIN and PEEK-MIN just look at or pop the last cell. INSERT walks from the end and shifts every smaller item one slot right: up to n shifts, about n/2 on average.
  • Link to sorting. Inserting all items and extracting them one by one is a sort. The unsorted array gives selection sort, the sorted array gives insertion sort. Both are Θ(n²).
  • Link to graphs. Dijkstra and Prim with an unsorted array as the queue cost O(V²), since every extraction scans all vertices. Tab 2 shows how to do better.

Cost model used in the counters: one comparison between two keys, one move = one array write (a swap counts as one move).

Binary min-heap. A complete binary tree stored in an array: the parent of index i is ⌊(i−1)/2⌋, the children are 2i+1 and 2i+2. The rule is that every parent is ≤ its children, so the minimum is always at index 0. INSERT places the new item at the end and sifts up. EXTRACT-MIN moves the last item to the root and sifts down. The tree and the array below it are the same data.

Analysis

  • Height. A complete tree with n nodes has height ⌊log₂ n⌋. A sift moves along one root-to-leaf path and does a constant amount of work per level, so INSERT and EXTRACT-MIN are O(log n). Sift-up does 1 comparison per level, sift-down up to 2.
  • INSERT is O(log n) in the worst case (new item is the smallest) but O(1) on average for random input, because most items are already near their final level.
  • BUILD-HEAP is O(n), not O(n log n). About n/2^(h+1) nodes sit at height h and each sifts at most h levels, so the total is Σ h·n/2^(h+1) ≤ n. Try the Build heap button and count the moves.
  • Heapsort = BUILD-HEAP + n EXTRACT-MINs = O(n log n), in place.
